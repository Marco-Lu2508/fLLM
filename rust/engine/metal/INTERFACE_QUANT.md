# Quantized linear kernels for Metal - interface contract

Verification level: **L0**. The MSL text was (1) parsed with the clang-based syntax shim of `mslcheck.sh`, (2) compiled as C++ with an
emulation of `simd_sum`, `threadgroup_barrier` and `simdgroup_matrix` and **executed on the CPU** (`emu/`, one C++ thread per Metal thread)
against `compute::dequantize` for every format, and (3) the Rust side (`src/backend/metal/weights.rs`, `weights/`) has CPU unit tests.
No kernel was ever compiled by the Metal compiler or run on a GPU; performance, register use and the real `simdgroup_matrix` /
`simd_sum` hardware behaviour are unmeasured.

`Stream::quantized_linear`: `out[tok][row_base + r] = scale * row_scale(r) * dot(x[tok], w[r]) (+ bias[row_base + r]) (+ out[...] if residual)`
for `tok < batch`, `r < rows`. `x` and `out` are f32. The Rust side plans every call: `plan_quantized_linear(quant, rows, cols, batch,
&MetalCapsLike) -> LinearPlan` (kernel name, function constants, grid, parameter block, optional prepass).

## Files

| file | role |
|---|---|
| `common.metal` | block decoders of all formats (`q_fmt_<fmt>::dec8`), `q_params`, `q_finish`, `Q_KERNEL`. Shared: prepended to every compile unit |
| `common_q_gemv.metal` | function constant `q_fc_nb`, matrix-vector body `q_mv_body`, kernel templates `q_mv_r4_t`, `q_mv_r2_t`. Shared |
| `common_q_gemm.metal` | matrix-matrix body `q_mm_body`, kernel template `q_mm_t<F, T>`. Shared |
| `q_mv_{legacy,kquant,fp}.metal`, `q_mm_{legacy,kquant,fp}.metal` | the instantiations (generated by `q_gen.py`, one `[[host_name]]` line per kernel); one Metal library each, compiled on first use |
| `q_prepass.metal` | `fllm_q_permute_x` |
| `emu/` | CPU emulation (README.md) |

The shared files contain no spelled-out `kernel` keyword (`Q_KERNEL` is a macro), so the source scanner of `pipelines/source.rs` treats
them as shared code. Sort order matters: `common.metal` first, then `common_q_gemm.metal`, `common_q_gemv.metal` (they are independent of each other).

## Formats and device layouts

`pack_weight(quant, rows, cols, raw) -> PackedWeight` (Rust). **Raw** = the device image is the GGUF tensor unchanged (`Cow::Borrowed`):
the kernels read the GGUF blocks, so a memory-mapped model can be bound without a copy (`MemoryManager::buffer_for_host_slice`).
**Planar** = two planes, plane 1 at byte offset `q_params::plane1` (multiple of 16).

| format (QuantType) | tag | QK | kernel block | layout | notes |
|---|---|---:|---:|---|---|
| Q4_0, Q4_1, Q5_0, Q5_1, Q8_0 | `q4_0` `q4_1` `q5_0` `q5_1` `q8_0` | 32 | 18/20/22/24/34 | raw | Q4_0/Q5_0/Q8_0 blocks are 2-byte aligned only (16 bit loads) |
| IQ4_NL | `iq4_nl` | 32 | 18 | raw | code book `KVALUES_IQ4NL` |
| Q2_K, Q3_K, Q4_K, Q5_K, Q6_K | `q2_k` .. `q6_k` | 256 | 84/110/144/176/210 | raw | 6-bit scales decoded in the kernel; Q3_K and Q6_K 2-byte aligned |
| IQ4_XS | `iq4_xs` | 256 | 136 | raw | |
| MXFP4 | `mxfp4` | 32 | 16 | planar | plane 0: the 16 code bytes of every block; plane 1: the E8M0 scale byte of every block (padded to 16) |
| NVFP4 | `nvfp4` | 64 | 36 | raw | UE4M3 scales; the per-tensor factor goes into `q_params::scale` (`DeviceWeight::scale`) |
| Q4Z32/64/128, Q4ZP32/64/128 | `q4z32` `q4z64` `q4z128` | 32/64/128 | group/2 | planar | plane 0: code bytes (value 2j in the low nibble); plane 1: one u32 per group: f16 scale bits \| zero << 16. Q4ZP: the permutation table is split off (`PackedWeight::perm`), see the prepass |
| MLX affine (`MLXA`, GGUF ids `0x8001_0000 \| bf16 << 12 \| (group / 32) << 4 \| bits`): 2, 3, 4, 5, 6, 8 bits x groups 32/64/128 x f16/bf16 scales = 36 `QuantType::Other(id)` | `mlx<bits>g<group>` (the bf16 variant shares the kernels) | 32/64/128 | group * bits / 8 | planar | plane 0: the codes of every group in the MLX word order (a little-endian bit stream, code i at bit i * bits; a chunk of 8 codes is `bits` bytes at a byte boundary); plane 1: one u32 per group: scale bits \| bias bits << 16 (binary16, or bfloat16 when bit 63 of `q_params::plane1` is set, which the planner does; the offset is the low 63 bits). `w = code * scale + bias`. Family `mlx` (`q_mv_mlx.metal`, `q_mm_mlx.metal`); `FLLM_METAL_NO_MLX=1` removes the formats from the capability list |
| F32, F16, BF16 | `f32` `f16` `bf16` | 8 | 32/16/16 | raw | "blocks" of 8 values; BF16 is converted by bit operations (no `bfloat` type needed) |
| FP8 E4M3 / E5M2 (`Fp8E4m3`, `Fp8E5m2`) | `fp8e4m3` `fp8e5m2` | 8 | 8 | raw | one byte per weight; scale through `q_params::scale` |
| FP8M (`Fp8Marlin`, GGUF 0x8000_0020) | `fp8m` | 8 | 8 | raw | E4M3 bytes, then one f16 scale per row at `plane1 = rows * cols`; applied after the dot product |

Not implemented: the other IQ formats (IQ1/IQ2/IQ3), Q8_1/Q8_K, the Marlin device layouts. `format_info(quant)` returns `None` for them.

**Alignment promised by the backend:** the weight buffer (buffer offset included) is 4-byte aligned, 16-byte aligned for F32/F16/BF16 (rows are
read as 16 bytes); activation (`x`) and prepass buffers are 16-byte aligned and `x_stride` is a multiple of 8 floats (`cols` is); `out` needs
4. GGUF tensors start at multiples of 32 in the file, `row_base`/row slices of a stacked tensor start at `row * row_bytes` (a multiple of 4 for all
formats with 4-byte reads, of 2 for the others, as the block sizes are).

## Parameter block `q_params` (buffer 4, 48 bytes, `QParams` in `weights/plan.rs`)

| field | meaning |
|---|---|
| `ulong plane1` | byte offset of plane 1 (planar formats; FP8M row scales), else 0 |
| `uint rows` | weight rows of this dispatch |
| `uint cols` | K (multiple of 8 and of QK) |
| `uint batch` | activation rows |
| `uint flags` | bit 0: add `bias[row_base + r]`; bit 1: `out +=` (fused residual; bind `out` read-write) |
| `float scale` | factor on top of the format's scales (`DeviceWeight::scale`), 1.0 normally |
| `uint out_stride` | floats between the outputs of two tokens (default `rows`) |
| `uint row_base` | first output feature of this dispatch (several weights into one buffer, e.g. fused QKV) |
| `uint x_stride` | floats between two activation rows (default `cols`) |
| `uint nb_blocks` | `cols / QK` |
| `uint pad` | 0 |

Rust: `LinearPlan::with_bias()`, `.with_residual()`, `.with_scale(s)`, `.with_output(row_base, out_stride)`; `QParams::to_bytes()` yields the 48 bytes
(or bind the `#[repr(C)]` struct with `DispatchBuilder::bytes`).

## Kernels

All kernels take buffers 0 weights (`device const uchar*`), 1 `x` (f32), 2 `out` (f32), 3 `bias` (f32, **always bind a buffer**, any small one
when `flags & 1 == 0`), 4 `q_params`. Weights/x/bias are `Access::Read`, `out` is `Write` (`ReadWrite` with the residual flag).

### `fllm_q_mv_<tag>_r4`, `fllm_q_mv_<tag>_r2` - matrix-vector (batch 1..8 per dispatch column)

* Function constant **500** (`q_fc_nb`, uint, required): tokens per dispatch column `nb` (1..8). Use `r4` (4 weight rows per simdgroup) for
  `nb <= 4`, `r2` (2 rows) above (register pressure).
* Threadgroup: `2 * simd_width` threads (2 simdgroups; `Q_MV_NSG`), no threadgroup memory.
* Grid: `x = ceil(rows / (2 * NR))`, `y = ceil(batch / nb)`, `z = 1`. With `batch <= 8`: `nb = batch`, `y = 1`. Larger batches without
  `simdgroup_matrix`: `nb = 8` and `y = ceil(batch / 8)` (tokens beyond `batch` are skipped).
* Work: lane `l` of a simdgroup decodes the 8-value chunks `l, l + width, ...` of its rows, multiplies them with the activations of all `nb`
  tokens (two `float4` loads per token and chunk) and reduces with `simd_sum`; lane 0 writes the results. Works for any simd width.

### `fllm_q_mm_<tag>_h`, `fllm_q_mm_<tag>_f` - matrix-matrix (batch > 8, prompt processing)

* `_h`: weights and activations rounded to half in the tiles (float accumulation) - the fast variant; `_f`: float tiles (exact up to float
  rounding; used for F32 weights and with `MetalCapsLike::exact`).
* Needs `simdgroup_matrix`, **simd width 32**, 128 threads per threadgroup (4 simdgroups, 2 x 2 of 32 rows x 16 tokens).
* Threadgroup memory slot 0: `14336` bytes (`_h`) / `20480` bytes (`_f`) = `(64 + 32) * 32 * sizeof(T) + 64 * 32 * 4` (`Q_MM_SHMEM_*`). 16-byte aligned base.
* Grid: `x = ceil(rows / 64)`, `y = ceil(batch / 32)`, `z = 1`. Tile: 64 weight rows x 32 tokens, K slices of 32 (the tail is zero filled).
* No function constants.

### `fllm_q_permute_x` - activation prepass of act-order GPTQ (`Q4ZP*`)

Buffers: 0 `x` (f32, `x_stride`), 1 `y` (f32, dense `batch * cols`, `PrepassPlan::output_bytes`), 2 `perm` (u32 x cols, `DeviceWeight::perm`), 3
`q_permute_params {batch, cols, x_stride, pad}` (16 bytes). Threadgroup 256 threads, grid `ceil(batch * cols / 256)`. `y[tok][c] = x[tok][perm[c]]`;
afterwards the main kernel reads `y` as its `x` (barrier between the dispatches: `y` is written by the first and read by the second). Several
weights reading the same `x` with the same permutation can share one prepass.

## Hardware check for the Mac test round

`src/backend/metal/weights/gpu_check.rs` runs every format on the GPU against `compute::dequantize` (sample weights from `weights/sample.rs`; matrix-vector
batch 1, 3, 8, matrix-matrix batch 9, 33 with half and float tiles; bias and scale on; 70 x 256 weights) and prints one `[ok]` / `[FAIL]` line per check with
the largest error relative to `sum |w x|`:

```
cargo test --release -p fllm-engine --features metal metal_quant_kernels -- --nocapture
```

The file is **not wired into `weights.rs`**: it uses the Metal core (`MetalContext`) and is therefore not part of the standalone kernel set. When the Metal core is built, add
`pub mod gpu_check;` to `weights.rs` (above `pub mod sample;`). It was type-checked and passes clippy `-D warnings` for `aarch64-apple-darwin` together with the Metal core (`--features metal --tests`). `gpu_check::run(&MetalContext)` can also be called from a `selftest-gpu` check. If a format fails, run the same shape
with `FLLM_METAL_SERIAL=1` first (rules out missing barriers; there are none between the prepass and the main kernel except the declared buffer access), then
compare the `[ok]`/`[FAIL]` pattern: only `_h` kernels failing points at the half tiles, only one format failing at its decoder (`emu/` runs the same decoder on the CPU).

## Reusing the bodies (non-matmul and recurrent kernels)

`q_fmt_<fmt>::dec8(w, g, c, plane1, out)` (common.metal) decodes 8 weights of any format from a `device const uchar*` base pointer; `q_mv_body<F, NR>` and
`q_mm_body<F, T>` take that base pointer, so an expert-wise matrix-vector product (MoE, base pointer from an `AddressTable`) or a quantized embedding
lookup (`dec8` of the row's chunks) can call them with another `w` (and `p.plane1` of that expert) instead of re-implementing the formats. All symbols are
prefixed `q_` / `Q_`; function constant 500 is reserved.

## Using the plan (sketch for the stream)

```rust
let caps = MetalCapsLike::new(info.simdgroup_matrix, info.bfloat, 32 /* or pipeline.simd_width() */, info.max_threads_per_threadgroup, info.has_unified_memory);
let plan = plan_quantized_linear(weight.quant_type, weight.rows, weight.cols, batch, &caps)?.with_bias().with_scale(weight.scale);
let constants: Vec<FunctionConstant> = plan.constants.iter().map(|c| FunctionConstant::u32(c.index, c.value)).collect();
let pipeline = pipelines.get(&plan.kernel_name, &constants)?;   // once per (kernel, constants), keep the Arc
// act-order weights: first dispatch plan.activation_prepass (pre.kernel_name, pre.slots, pre.params.to_bytes(), pre.dispatch_dims()) and bind its output as `x`
let (groups, threads) = plan.dispatch_dims();
let mut d = rec.begin(&pipeline)?;
d.read(plan.slots.weights, &w).read(plan.slots.x, &x).write(plan.slots.out, &out).read(plan.slots.bias, &bias)
    .bytes(plan.slots.params, &plan.params);                 // QParams is #[repr(C)], 48 bytes, no padding
for (slot, bytes) in &plan.threadgroup_memory { d.threadgroup_memory(*slot, *bytes as usize); }
d.threadgroups(groups, threads)?;
```
Pipelines should be looked up once per (kernel, batch class); `all_kernel_names()` lists everything for `PipelineCache::prewarm`.

## Numerics

* mv and `_f` kernels: float arithmetic, the sum order differs from the CPU (per-lane partial sums, `simd_sum`); relative error to an f64 reference
  about 1e-7 of `sum |w x|` in the emulation. `_h`: about 1e-4 (half rounding of weights and activations, emulated with `_Float16`).
* MXFP4 scale bytes 0 and 1 (2^-127, 2^-128) are denormal floats; Metal flushes denormals (fast math), so such blocks decode as 0 on a GPU, unlike the CPU
  decoder. Real checkpoints do not use them.
* BF16/E4M3 NaN patterns propagate; E5M2 infinities propagate.

## Known weaknesses (L0)

* Never run on a GPU. Unknown: whether the Metal compiler accepts every construct (explicit template instantiation with `[[host_name]]` and
  `decltype`, `static constant constexpr const` members, `simdgroup_matrix<half,8,8>` arrays with mixed half x half -> float accumulation,
  `ulong2(0, 0)` origin argument of `simdgroup_load`), and how much the generic 8-chunk decoders cost: each lane decodes (and for K-quants re-derives the
  scale of) one chunk of 8 values at a time, so the decode is probably ALU bound compared with llama.cpp / MLX style kernels that amortise scales over 16..32
  values. All tuning constants (2 simdgroups, 4/2 rows per simdgroup, 64 x 32 x 32 tiles, no padding against threadgroup bank conflicts, 128 threads) are untuned guesses.
* No int8 / `simdgroup` fast path for quantized activations (Apple GPUs have no int8 dot hardware before M5).
* The matrix-vector kernels load every activation chunk once per row group (4 or 2 rows); a block of 8 tokens costs 16 `float4` registers.
* `row slices` of oversized weights (larger than `maxBufferLength`) are not implemented: the planner supports `row_base`/`out_stride` for it, but `pack_weight`
  expects the whole tensor. MoE experts are separate tensors (`upload_pointer_table`).
* The half variant is not selected automatically when `exact` is set; there is no automatic fallback to a smaller tile for devices with < 20 KiB threadgroup memory
  (all Apple GPUs have 32 KiB).
