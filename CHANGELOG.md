# Changelog

All notable changes to fLLM are documented in this file. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/)
and the project aims to follow [Semantic Versioning](https://semver.org/) once it leaves the 0.x series (0.x releases may change
behaviour between versions).

## [Unreleased]

### Fixed
- `serve --device cuda --embeddings` (and a vision model with `--mmproj`) failed to start with "unsupported Rust GPU backend cuda": the small helper models (text encoders, vision towers) now run on the CPU when the device is `cuda`, `hip` or another one they cannot use. Found by the A100 run of the Colab check.
- Beam search ignores the repetition penalty a model recommends for sampling instead of refusing every request on such a model (a penalty the request itself asks for is still refused).
- Helm chart: the size and time of the output cache were written as `6.7108864e+07` and ignored by the server (so the default stayed); they are whole numbers now, and `helm lint` passes. `appVersion` follows the release.

### Added
- **An in-app browser for the coding agent** (off until Settings > Browser > "Let the agent use a browser" is switched on). The agent gets `browser_open`, `browser_snapshot` (the page as compact text, a numbered `ref` on every link, button and field, from the accessibility tree), `browser_click`, `browser_type`, `browser_select`, `browser_press`, `browser_scroll`, `browser_back`, `browser_screenshot` (PNG; attached for a model with vision), `browser_tabs` and `browser_close`; every result lists the console errors, uncaught exceptions and failed requests of the page. They drive a real Chrome, Chromium, Edge or Brave over the DevTools Protocol with a small WebSocket client of our own (no new dependency), headless by default, in a profile folder of fLLM's own (`browser-profile`, never the user's browser), with downloads and permission prompts refused. Safety: only http and https; no `file:`, `chrome:`, `devtools:`, `view-source:`, `javascript:` or `data:` pages; link-local and metadata addresses never; `localhost` only while a workspace is open, the local network only when allowed; names are resolved and every address checked; every request of a page is gated, and a page from the internet cannot load local addresses; the controls are reachable from this computer only, with or without an API key; the browser dies with the session and with the server, also when the server is killed. The Code page has a **Browser panel** (closed by default) with the live page, an address bar, clicks, typing and scrolling forwarded to the page, and a comment mode: click an element, write a note, and the note with the element's ref goes with the next message. Tools are permission category `network` (ask first, "Always" per session, rules by the page's address, deny wins, turbo skips the questions). Verified with Chromium 156 on Linux in Docker and by unit tests; not verified on Windows (Edge, Chrome), macOS, with a visible window, or in the desktop app. See [The browser](docs/user/studio.md#the-browser); Docker images contain no browser ([docker.md](docs/docker.md)).
- Jump-forward decoding for grammar-constrained requests (`response_format`, `grammar`, `tool_call_grammar`): where the grammar forces the next characters (the fixed keys and punctuation of a JSON schema, literals in a Lark or GBNF rule), the engine appends them as tokens and the model processes all of them in one forward pass instead of one pass per token. The reply and `usage` are unchanged; with single-character vocabularies the output is token for token identical to decoding without it (tested over many seeds and schemas), with subword vocabularies the text is the same but the token sequence can differ. On the CPU test model the number of forward passes drops by about 5x for compact JSON schemas and literal grammars (for example 486 to 96 over 12 requests); wall-clock speed on real models has not been measured. `--no-jump-forward` or `FLLM_JUMP_FORWARD=off` turns it off; `/metrics` gains `fllm_jump_forward_tokens_total` and `fllm_jump_forward_steps_total`. See [Jump-forward decoding](docs/server-api.md#jump-forward-decoding).
- **Beam search** (`use_beam_search`, with `best_of` as the beam width of 1 to 8, `n` hypotheses returned, `length_penalty`, `early_stopping` `true|false|"never"`) on `/v1/completions` and `/v1/chat/completions`, non-streaming. Beams are ordinary scheduled sequences that share their prefix KV blocks; the score is the sum of token log-probabilities over `length ^ length_penalty`; stop tokens, stop strings, `min_tokens`, `max_tokens`, `logit_bias`, `allowed_token_ids` and `bad_words` are respected. Width 1 equals greedy decoding. Streaming, `logprobs`, repetition/presence/frequency penalties, grammars and images are refused with a clear `400`; a width or token budget the KV pool or the sequence slots cannot hold is refused up front (`400`, or `503` while other searches hold the slots) instead of being queued. See `docs/api-compat.md`.
- **`--multi-step N`** (alias `--num-scheduler-steps`): up to N decode rounds per scheduler round while the batch does not change. Off by default; it applies to the CPU backend only and is ignored (with a message) on accelerators until it is verified there. The output is token for token the one of single steps; speculation, grammar-constrained requests, media and beam search keep single steps. See `docs/speculative-decoding.md` and `docs/dev/step-api.md`.
- **MXFP4, bitsandbytes, MLX, EXL2, EXL3 and PyTorch weights now load without a GGUF file too** (`run`, `serve`, `pull`; `--no-direct-load` / `FLLM_NO_DIRECT_LOAD=1` still converts and caches, `--direct` still forces). Each format moved only after a test showed the direct load equal to the converted file byte for byte (every tensor, dimension, type and metadata value): gpt-oss and compressed-tensors MXFP4; bitsandbytes NF4/FP4 (block 64/128, double quantization) and int8; MLX affine with 2 to 8 bits; EXL2 and EXL3; PyTorch ZIP archives (stored storages stay slices of the archive). The decoder gives identical logits for MLX, bitsandbytes, MXFP4, EXL2 and a PyTorch `.bin` (EXL3 is compared byte for byte only: its tensors need dimensions of 128). MLX, bitsandbytes and EXL weights are expanded to 16-bit in memory, so the free-memory check counts four (MLX, bitsandbytes) or five (EXL) times their size and falls back to the cached conversion for models that would not fit. The fixtures hold random codes in each layout, not real models; large real checkpoints are not measured. A test now also proves that a malicious PyTorch pickle (`os.system`, `eval`, `subprocess`, `STACK_GLOBAL`, `BUILD` and the object opcodes) is refused and runs nothing.
- Settings > Tools (MCP) > "Find servers": search the official MCP registry (registry.modelcontextprotocol.io) or Smithery, and put a hit into the form below with the command (`npx`, `uvx`, `docker`) or the remote address it needs, ready to check and save. The values to fill in (tokens, folders) are listed. Nothing runs before the person saves it.
- Settings > Skills and schedules > "Find skills on GitHub": type a repository (`owner/repo`, a GitHub address, or the command of a skills directory such as `npx skills add owner/repo`), see its skills with their descriptions and install the ones you want into your skills folder. It needs no account. A link opens the skills.sh directory for browsing, and with a Vercel token (saved on this computer, never shown again) the same card searches the directory and its most installed, trending and hot skills, installs a skill from it and shows the security audits of skills.sh. The front matter reader now understands YAML block values (`description: >`).

- **Command sandbox for Windows** (implemented; checked on one Windows 11 machine: a write outside the workspace is denied, git, node and python run inside; not yet checked on other machines): `FLLM_SANDBOX=workspace` (or Settings > Runtime) runs the `bash` commands and background jobs of the agent through a hidden `fllm-rs sandbox-exec` launcher, under a restricted token at low integrity level inside a job object. Enforced: the process tree dies on stop, timeout or server exit; writes only inside the workspace and a private temp folder (the workspace gets a low integrity label once, via `icacls`; drive roots, the profile, personal and system folders are refused); privileges dropped and administrator groups deny-only; at most 512 processes and three quarters of the memory; no clipboard, desktop or handle access; secret-looking environment variables removed. Not enforced: reading files and the network. `strict` is unavailable on Windows (no AppContainer) and refuses commands with a message. A self-test on the machine decides availability, and `GET /api/studio/agent/sandbox` and Settings > Runtime now list what is and is not enforced and how well it is verified. Without a working sandbox commands still run unwrapped as on Linux, but a sandbox that works and fails to start a command returns an error instead of running it unsandboxed.
- **Seatbelt profile for macOS** (unverified, same self-test guard): `sandbox-exec` with a write-confined profile for `workspace` and `strict`.

### Fixed
- `Runtime::fork_sequence` took one reference too many on every block it copied, so the blocks of a forked sequence were never given back. It now shares completely computed blocks by reference count (copy-on-write) and copies only the tail block, so a fork costs one block instead of a copy of the whole sequence.
- MLX checkpoints that carry their bits and group size only as `quantization_config` (mlx-lm writes the same dictionary under both names) failed with "no bits/group_size in the quantization config"; the converter now reads either.
- The Sampling panel (and the other pop-up panels above the message box) is no longer cut off at the top of the window: it opens below when there is not enough room above, never grows beyond the window and scrolls inside.
- A chat answer that ended in the middle of a tool call (Gemma's `<|tool_call>call:...`) no longer shows the raw markup, and answers with tools get room for thinking, searching and writing (at least 2048 tokens or half the context). Max tokens is automatic by default (what is left of the context window after the prompt, up to 131072) instead of 256, and its slider reaches the context size of the loaded model. When the model runs out of tokens before it writes an answer, the page says so instead of "did not write an answer".

### Changed
- The sandbox mode defaults to `off` on Windows and macOS (it stays `workspace` on Linux), because the new mechanisms there are not verified on real machines yet. Nothing changes for anybody who does not turn it on.
- fLLM has its own folder for settings, plugins, sub-agents, hooks, skills and notes (`%LOCALAPPDATA%LLM`, `~/Library/Application Support/fLLM`, `~/.local/share/fllm`; `FLLM_HOME` changes it). Before, they lay inside the Hugging Face cache. The first start moves the old files over. Models stay in the Hugging Face cache when it exists and go to `models/` in the own folder on a computer without one. The container images set `FLLM_HOME` to the volume path they used before.

## [0.1.11] - 2026-10-28

Safetensors checkpoints load without a GGUF file, the Studio looks like an app (own menus, lists, tooltips and dialogs), the app no longer loads a model when it opens, and the server can be administered safely: API keys with an admin right, a Settings > Engine page for every cache and telemetry option, and containers restart in place.

### Changed
- The output cache holds at most 64 MB by default (was 256 MB).
- The app no longer loads a model when it opens. The last model loads with your first message in Chat or Code, which is then sent on its own once the model is ready. Settings > Models > "Load the last model when the app starts" brings the old behaviour back.
- The settings pages for hooks, agents, prices, plugins, runtime, embeddings and web search open without a model loaded.

### Security
- The `/admin/*` routes (drain, empty the cache, effective settings, telemetry) answer only this computer, or another computer with an API key that has the **admin right**. Keys given with `--api-key` are admin keys; keys made on the Studio page are admin keys only when "Admin" is ticked. A key made for chatting no longer reaches them, and while keys are in use only an admin key (or this computer) can make or remove keys, so no user can make themselves an admin.
- With `FLLM_CACHE_SCOPE=tenant` the output cache is separated by the API key of the caller (together with the `user` field), not by the `user` field alone, which any caller could choose.
- While API keys are in use, changing the server through `/api/studio/*` (settings, models, updates, keys) needs an admin key or this machine; before, every key could do it.

### Added
- **Safetensors checkpoints load without a GGUF file.** `run`, `serve` and `pull` give the engine a view of the checkpoint that looks like the converted GGUF: metadata from `config.json` and the tokenizer, unchanged tensors as slices of the memory-mapped files, every other tensor produced once by the converter's own writer into memory. The disk holds the checkpoint only and the first start no longer waits for a conversion. This is the default for unquantized, AWQ, GPTQ, FP8, ModelOpt NVFP4 and compressed-tensors safetensors; EXL2/EXL3, MXFP4, bitsandbytes, MLX and PyTorch weights still convert and cache a GGUF. `--no-direct-load` (or `FLLM_NO_DIRECT_LOAD=1`) always converts, `--direct` forces the direct load for any checkpoint the converter understands, and a finished conversion in the cache is still preferred without `--direct`. Checkpoints larger than the free memory fall back to the file-based route. Checked byte for byte (every tensor, type and metadata value) and by logits and a greedy completion through the real `serve` binary against the converted file, on tiny synthetic models only; not yet measured on large real models or on a GPU. Details and the exact tests: [docs/rust-formats-and-import.md](docs/rust-formats-and-import.md).
- **`--quant` while loading**: `run`/`serve --quant q4_k_m` (and the other presets) re-encode an unquantized checkpoint tensor by tensor as it loads, with no file and without the whole model ever existing as F16; the result is byte-identical to `convert` followed by `quantize`. `--outtype f16|f32` works while loading as well.
- Docker and Kubernetes: the options of the page apply to `serve` too, the CPU Compose file keeps them in a volume, and restarting or loading another model inside a container replaces the server in place instead of ending the container.
- Settings > Engine also has the folder and size for prompt blocks on disk (`FLLM_KV_DISK_DIR`), with live numbers and buttons to delete them or forget the shared prompts in memory.
- Settings > Engine: the output cache (on or off, size, time, who shares it), prefix sharing, the prefix separator, what happens when memory runs out, telemetry address and name, plus live numbers, "empty the cache" and "stop taking new requests". The options are saved and take effect when the server restarts (a button restarts it).

### Fixed
- Drop-down lists, tooltips and the arrows of number fields are drawn by the app instead of the browser, and buttons and menus can no longer be selected as text, so the window looks like an app.
- A right click on a chat, a project or a message lists its actions (pin, rename, archive, delete, copy, rewind ...). Sliders are drawn in the look of the app.
- A right click opens a menu of the app (cut, copy, paste, select all, copy link, copy code or text) instead of the browser's.
- Questions (Turbo, removing a provider, plugin, MCP server or the NPU runtime) appear inside the app instead of the browser's own box, and a right click no longer opens the browser menu (text fields keep theirs).
- **Regression tests through HTTP**: four tests now drive `/v1/chat/completions` and `/ready` instead of calling functions — an identical deterministic request must be a cache hit, a request without an explicit greedy temperature must stay out of the cache, a draining server must answer 503, and two identical requests at the same time must share one computation (one follower). Each of the four was mutation-checked: reverting the fix makes it fail. All three failed against the code of this session before the fixes above.
- **OTLP attribute shape**: every span attribute is now `{"key": …, "value": {"stringValue"|"intValue"|"boolValue": …}}` as the protocol requires; before, a custom attribute carried `keyValue` next to `key`, which a real collector would ignore.
- **`fllm_otel_spans_sent_total` / `sent`** counted nothing: the exporter thread sent batches but never reported them. It now counts every batch the collector accepted (HTTP 2xx).
- **The output cache never applied to chat completions**: the eligibility check required "no reasoning spec", but the chat path always passes one (even for a model without a reasoning parser). A live server now shows `hits: 1, stored: 1` for a repeated deterministic prompt.
- **Draining was not enforced on the chat path**: `openai_generate` had no admission check of its own, so `/v1/chat/completions` answered 200 while `/ready` already reported `draining`. The shared generation path now refuses with 503 too.
- The columns of the usage and cost table line up (numbers right-aligned).
- The glow around the message box is even on every side; before, the top corners stayed dark.

## [0.1.10] - 2026-10-27

Fixes the header menus of 0.1.9 (the assistant list could not be used), makes the Code page say why it is unavailable, lets the coding agent create its own sub-agents, and turns conversation lookup on by default.
### Changed
- Conversation lookup (`--speculative suffix`) is on by default for models without a recurrent state on the processor and on Vulkan / DirectX graphics (`--speculative off` or `FLLM_SPECULATIVE_DEFAULT=off` keeps it away; CUDA, HIP and Metal stay off until their verification kernels have run on hardware). Same text as without, up to twice the speed on code edits, summaries and agent loops, no cost when it finds nothing.

### Fixed
- Release signing (Cosign) is tried three times: one archive of 0.1.9 failed to sign when many jobs asked the signing service at once.
- The menus of the page header (model, assistant, chat) were painted under the page since the new design system: the header had its own layer without a stacking order, so assistants could not be picked and the text of the start page showed through. Opening one menu closes the other.
- Code page: "The coding agent is not available." now says why (the server without a model has no agent: load a model first), shows the HTTP status for other errors, and has a *Try again* button.

### Added
- **`Runtime::fork_sequence`**: copies a running sequence with its KV blocks (block by block via `copy_prompt_block`, which handles both uniform and layered geometries), gives everything back on failure, and hands the copy to admission as already-computed. This is the primitive beam search needs; the search itself is not built yet.
- **`cache_salt` per request**: the salt names the namespace of an answer — it seeds the prefix chain (`Sequence::prefix_salt`) and is part of the output-cache key, so two tenants with different salts never see each other's cached answer or KV blocks. Live: salt B regenerated after salt A had cached the same prompt; the same salt was a hit.
- **Disk-tier writes run on their own thread**: the step path exports the block and hands it to a bounded queue (256), so file I/O never sits between two tokens; a full queue drops the block instead of delaying a token.
- **`GET|DELETE /admin/kv-tier`**: the disk tier reports its directory, budget, used bytes, spills, hits, misses and drops; `DELETE` removes every stored block and answers how many. Live: `used_bytes 12780`, `{"removed":3}`, back to `0`.
- **`DELETE /admin/prefix-cache`**: empties the cache and hands the blocks back to the allocator (`Scheduler::clear_prefix_cache`), answering how many entries were dropped. Verified live: 3 entries → `{"dropped":3}` → 0.
- **`GET /admin/prefix-cache`**: what the prefix cache holds — entry count, hit counter, every block with its chain hash and token count, and the radix tree itself. Runs through the inference worker, because the cache lives on that thread.
- **KV disk tier reads**: `Runtime::warm_prefix_cache` rebuilds chains from disk at the first step (root first, whole path via `insert_path`), so a restart keeps the prefix cache. Live: `warmed 4 prefix blocks` and `cached: 64 / 76` on the first request of a fresh process.
- **KV disk tier format v2**: every block stores its parent hash and its tokens, so a chain can be rebuilt in order (`FLLMKV02`); verified live with a four-block chain.
- **KV disk tier (write-through)**: cached prefix blocks are written to `FLLM_KV_DISK_DIR` as soon as the prefix cache registers them (`Scheduler::insert_full_blocks` → `pending_spills` → `Runtime::spill_pending`), while the block is alive so its KV still belongs to its hash. Verified live: one chat request produced three `.kv` files of 4120 bytes. Reading back is not wired yet (`docs/dev/kv-disk-tier.md`).
- **KV disk tier (storage)**: `mem/kv_tier.rs` writes evicted KV blocks to `FLLM_KV_DISK_DIR` under their chain hash with an LRU budget, atomic renames and a header check; not wired into the engine yet (`docs/dev/kv-disk-tier.md`).
- **Design notes**: `docs/dev/step-api.md` (the seam beam search, multi-step and jump-forward need) and `docs/dev/kv-disk-tier.md`.
- **`FLLM_PREFIX_SALT`**: seeds every prefix chain, so two deployments can never reuse each other's KV blocks for the same prompt.
- **`GET /admin/config`**: the effective settings in one place — cache identity and statistics, prefix cache, preemption policy, telemetry, coalescing, sandbox, ready/draining.
- **Request coalescing**: identical deterministic requests that are in flight at the same time are computed once — the first leads, the rest wait for its answer (and learn when it failed instead of hanging).
- **Metrics**: `/metrics` now reports draining state, coalescing counters and exported spans next to the cache counters.
- **Tenant-scope warning**: a tenant-scoped output cache next to a running prefix cache logs a warning, because KV blocks would still be shared.
- **OTLP telemetry**: one span per finished answer, exported as OTLP/HTTP JSON to `FLLM_OTEL_ENDPOINT` by a background thread (no SDK, no new dependency), with `GET /admin/telemetry` for its state (`docs/telemetry.md`).
- **Draining**: `POST /admin/drain` refuses new work (`503` + `Retry-After`) while running requests finish, `/ready` reports `draining`; `DELETE /admin/drain` resumes. Makes rolling restarts safe.
- **Router metrics**: `GET /router/metrics` exposes routed requests, per-backend requests, failures and health in Prometheus format.
- **Prefix-cache switch and preemption policy**: `FLLM_PREFIX_CACHE=off` stops any KV sharing between requests (for tenants that must not share), `FLLM_PREEMPTION=swap` keeps the KV of a preempted sequence in host memory instead of recomputing it.
- **Output cache**: deterministic requests (`temperature = 0`, one choice, no tools/images/logprobs) are answered from a
  SHA-256-keyed, byte- and age-bounded cache instead of being generated again, with tenant-scoped namespaces
  (`FLLM_CACHE_SCOPE`), `/admin/cache` (stats + clear) and its own Prometheus counters (`docs/output-cache.md`).
- **`fllm-router`**: a prefix-aware router in front of several servers — the same prompt beginning always lands on the same
  backend, so the prefix cache keeps working across a fleet; failed backends are skipped and health is exposed at
  `/router/stats` (`docs/router.md`).
- **Benchmark client** `scripts/bench.py`: one client for fLLM, vLLM, SGLang and llama.cpp, measuring TTFT and ITL
  percentiles plus throughput at a given concurrency, with results as JSON (`benchmarks/README.md`).
- **Kubernetes and Helm**: `deploy/k8s/` (server, router, model volume, probes) and `deploy/helm/fllm/` with cache, GPU
  resources and readiness settings.
- Code agent: the `create_agent` tool writes a reusable sub-agent (name, description, tools, instructions) for this folder or for every folder, after the user agreed; the `task` tool starts it by name afterwards. Not offered in plan mode.
- Load dialog: *Conversation lookup* (`--speculative suffix`) and a *Browse...* button for the draft model (any GGUF file on the computer; the server still checks that it is smaller and shares the vocabulary). Measured on Gemma 4 E4B, CPU of a server (10 cores): repeating and extending code 19 -> 37 tokens/s with conversation lookup (26 with prompt lookup), a free story 21 -> 28 (prompt lookup: 17, slower than none); the text is the same as without. On Gemma 4 with Vulkan the text is the same too.

## [0.1.9] - 2026-10-27

Gemma 4 on graphics chips, a faster Vulkan prompt path, CPU answers on par with llama.cpp on server processors, a fix for 16 users on CUDA, and a large step for the Studio and its coding agent (sandbox, hooks, plugins, sub-agents, language servers, worktrees) with a new look.

### Changed
- **New design system** (`webui/theme.css`, loaded last): OLED-dark slate and warm paper light theme, signal-green accent with seven alternatives in the accent picker, 8 px grid, 11–34 px type scale, mono for meta, floating sidebar rail, centred 900 px reading column, raised composer, bento starter cards, quiet focus rings and reduced-motion support. The empty chat no longer shows a flat sparkline.

### Added
- **One click to the first model**: the empty chat screen offers the recommended model with its quantization and size and downloads it in place (progress, pause, resume, then load). Nothing has to be chosen in a terminal.
- **Sandbox and turbo in the page** (Settings > Runtime): `sandbox` as `off`/`workspace`/`strict` and a turbo switch that removes every permission question and the sandbox, kept in `runtime.json`; the environment still wins, and the page says when `bwrap` is missing. `/turbo` and `/sandbox` in the agent.
- **Web search with several engines**: DuckDuckGo and Wikipedia work without a key or a server, SearXNG and Brave can be added (Settings > Search), results are merged and every answer reports per engine what happened. Routes `GET`/`POST /api/studio/search/engines`, `POST /api/studio/search`.
- **Skill library and import**: six built-in skills install with one click, and *Import from URL* takes any `SKILL.md` over http(s).
- **Notes between sessions**: the `session_note` tool leaves a handover note in `.fllm/messages.json`, and the chat header shows an *Inbox* button with the number of waiting notes; one click inserts a note into the message, another marks it done. No background loop is pretended — the note waits until a chat is opened.
- **Automatic approval of harmless commands**: a fixed table (reading, building, testing, git reading and staging) decides which shell commands run without a question; redirects into real files, heredocs, risky substitutions and interpreters that would run arbitrary code still ask, and network, MCP and edit calls always ask. A deny rule beats it. `/autoapprove on|off` switches it, the tool card says why a call was approved.
- **`notebook_edit` tool**: replace, insert or delete one cell of a `.ipynb` without touching the JSON around it; replacing a code cell clears its stale output and execution count, and the answer shows the notebook as text.
- **MCP resources**: `resources/list` and `resources/read` (with paging, and an empty list when a server does not support them), a *Resources* button per server on the MCP page, and the `mcp_resource` tool for the model. Routes `POST /api/studio/mcp/resources` and `POST /api/studio/mcp/resource`.
- **Worktrees** for the coding agent: `/worktree new <name>` runs a change in its own `git worktree` on its own branch (added to `.git/info/exclude`, so it never shows up as untracked), `/worktree leave` returns to the main tree, `/worktree remove <name>` deletes the checkout, and `/batch <name> <task>` creates the worktree and runs the task there in one step. Route `POST /api/studio/agent/worktree`.
- **`lsp` tool**: real language-server answers instead of guesses — `diagnostics` for a file (types, imports, borrows, with line and column), `symbols` for a workspace symbol search and `definition` for a position. Uses rust-analyzer, typescript-language-server, pyright-langserver/pylsp, gopls or clangd from `PATH`, and says which one is missing instead of pretending.
- **Hybrid document search** (Settings > Search): an embeddings server (`fllm-rs serve --encoder`, or any OpenAI-compatible `/v1/embeddings`) makes the passage ranking 60 % BM25 and 40 % cosine, so a passage is found when the question uses another word for the same thing. Vectors are computed once per chat; without an address the search stays keyword-only. Routes `GET`/`POST /api/studio/embeddings`, `POST /api/studio/embed`.
- **Plugins from a repository**: the Plugins page installs from a git URL (depth 1, optional branch, no prompt for a password), so a plugin can live in its own repository instead of a local folder.
- **Plugins** (Settings > Plugins): `plugins/<name>/` with a `plugin.json` and optional `skills/`, `agents/`, `commands/` and `hooks.json`. Contributions are read at request time, never merged into your own files, so removing the plugin removes everything it added; they are read-only (your own skill of the same name wins), and a plugin hook gets `FLLM_PLUGIN_DIR` so it can run its own scripts. Installing from a folder refuses links, more than 5,000 files and more than 50 MB.
- **Remote MCP servers** (Streamable HTTP): a server entry may carry a `url` (and `headers`, where `${NAME}` is expanded from the environment at request time) instead of a command. One POST per message, the answer as JSON or as an event stream, and the `Mcp-Session-Id` is sent on every later request. The Tools (MCP) page has a URL field and a header box.
- **Rewind in a chat**: a button on every message ends the conversation at that message without deleting anything — the later
  messages stay attached to the node and are detached from the visible path, with Undo in the notice.
- **Command sandbox** (`FLLM_SANDBOX=off|workspace|strict`): `bash` and background jobs of the agent run under bubblewrap with the root filesystem read-only, the workspace writable, a private `/tmp` and own PID/IPC namespaces; `strict` also removes the network. Without `bwrap`, or when user namespaces are forbidden, commands run as before and `GET /api/studio/agent/sandbox` (and `/sandbox`) say why instead of pretending.
- **Hooks** (`hooks.json`, Settings > Hooks): shell commands at `pre_tool_call`, `post_tool_call`, `on_file_edit`, `on_session_start` and `on_session_end`, with a JSON payload on stdin and the exit code as the decision (`0` passes and adds notes, `2` blocks the call). The UI has a matcher, a command and a timeout per hook plus a test button; the agent routes run them around every tool call.
- **Your own sub-agents** (`agents/<name>.md`, Settings > Sub-agents): a Markdown file with `name`, `description`, `tools`, `model` and `max_steps` in the front matter and the instructions as the body. The `task` tool offers them by name, keeps their tool list, runs them on their own model and treats a list without writing tools as read-only.
- **`review` tool and `/review` / `/security-review`**: the working-tree, index or branch diff plus the findings of a fixed rule set (secrets, key formats, eval/exec, shell with interpolation, SQL by concatenation, conflict markers, plain http, TODO, debug output, `unwrap()`, `unsafe`, swallowed errors) with file, line and severity. `/security-review` keeps the security rules only.
- **Usage and cost** (Settings > Usage and cost, `/cost`): token counts per model kept in the browser, with a price table (`prices.json`) the user fills in for models behind a provider. A local model stays unpriced rather than showing an invented dollar amount.
- `FLLM_STUDIO_DEV=<dir>`: `serve`/`studio` serve the page from that folder on every request instead of the copy embedded at build time, so a CSS or JS change shows up on reload without a rebuild.
- Hybrid models keep a KV cache only for their attention layers: the Gated DeltaNet / Mamba layers of Qwen3.5, Qwen3-Next, Nemotron-H and similar models hold a recurrent state and no keys and values, but the pool reserved room for them too. Qwen3.5 (6 attention layers of 24) now needs a quarter of the KV memory: 1.77 instead of 7.1 GB for the same 9024 blocks, so four times the users or context fit on a card. `FLLM_FULL_KV=1` restores the old layout.
- Gemma 4 on the graphics chip: the device pass now runs the per-layer embeddings, the layer output scale, the value norm, layers whose values are their keys and layers that read an earlier layer's cache (the per-layer weights are uploaded as Q8_0). Measured on an Intel Core Ultra 5 235U (Vulkan) with Gemma 4 E4B Q4_K_M: answers at 12.7 tokens/s (llama.cpp 12.6), prompts at 115 tokens/s (llama.cpp 167); before, the model failed on the device.
- Vulkan prompt speed: the quantized matrix kernel computes 8 x 4 outputs per invocation on a 128 x 64 tile and its loaders read neighbouring bytes of a row (`FLLM_VK_MM_TM`, `FLLM_VK_MM_KS` for tuning), and the Gated DeltaNet recurrence runs over 16 value columns per workgroup with subgroup shuffles instead of one workgroup and a dozen barriers per token and head (`FLLM_VK_DELTA_COLS=0` keeps the old shader). Qwen3.5-2B Q4_K_M, 505-token prompt on the same laptop: 351 tokens/s (0.1.8: 245, llama.cpp: 374).
- Vulkan: a prompt attention kernel with 64 query rows per workgroup on devices that allow 512 invocations (`attn_prefill_*_r64`; `FLLM_VK_ATTN_ROWS=16` keeps the 16-row kernel): +7 % prompt speed at 2000 tokens on Intel Xe-LPG.
- The scheduler now gives running answers their token before new prompt chunks (`--chunked-prefill-policy decode-first` is the default): with several users the first ones get their answer streamed while the later prompts are still read, instead of everyone waiting until the last prompt is done (4 users with 2000-token prompts on Vulkan: first tokens after 9 to 32 s instead of all after 31 s). `prefill-first` restores the old order.
- `scripts/bench-load.ps1`: fLLM, llama.cpp and Ollama under load (prompts of several lengths, several users at once, total and per-user speed, time to the first token).
- `/skill` in the chat and on the Code page: the model writes a skill from the conversation and shows it for approval.
- `FLLM_VK_PROFILE=N` prints the shader table every N command buffers, summed over all recorders of the process.

### Fixed
- A chat on a model with a very small context (under 2048 tokens) failed with "the prompt does not fit": the system prompt plus the tool schemas took more room than the model has. Such models now get a two-line system prompt and no tools, and the page asks for at most a quarter of the window as `max_tokens`, which leaves room for the answer (a 512-token model: 683 tokens before, 249 after the change).
- CPU answers with small models were up to 30 % slower than llama.cpp on server processors: the thread measurement at start-up skipped models whose largest matrix is under 8 MB (it now streams the same projection of several layers, 96 MB per pass, and measures every model), and the Gated DeltaNet recurrence woke rayon's sleeping workers in every layer of every token instead of using the spinning ones. Qwen3.5-2B Q4_K_M on an AMD EPYC VM with 10 vCPUs: 46 to 55 tokens/s before, 65 after (llama.cpp 63 to 76 on the same, busy machine).
- CUDA: 16 simultaneous users (or a few at long contexts) failed with "illegal memory access": an attention call staged its lengths, then grew the metadata ring for its block tables and freed the memory the lengths were in. Found and verified on a Colab L4 (16 of 16 requests answered afterwards).
- Models with recurrent layers (Qwen3.5, Mamba) on a GPU: the memory plan now leaves room for the recurrent states of all sequences; before, the KV pool took the whole card and a busy step ran out of memory.
- A model step that failed (for example a device error under load) stopped the whole server; now its requests get the error, the error is logged at once, and the server keeps serving (three failed steps in a row still stop it).
- Gemma 4 on the CPU: the fast attention kernel now takes the sliding window and the score scale, so the model no longer uses the scalar reference in every layer (Core Ultra 5 235U, Gemma 4 E4B Q4_K_M: prompts 34 instead of 18 tokens/s, answers up to 8.7 instead of 3 to 4).
- Gemma per-layer weights stored as bf16 or f16 now go to the device as Q8_0 as well (the projection of the per-layer inputs ran in the slow bf16 kernel).
- An explicitly chosen device that cannot run a model (for example Gemma 3n on Vulkan) no longer stops the server: the model runs on the CPU and the reason is logged.
- Gemma 4 on Vulkan and the NPU failed with "rope width 512 invalid for head width 256": the device pass used one rotary width for all layers.
- Windows: the low-power efficiency cores of Intel Core Ultra are told from the other efficiency cores by their cache (Windows gives them the same efficiency class), so `--threads auto` picks 8 instead of 9 threads on a Core Ultra 5 235U; an explicit `--threads n` gets the same core placement as the automatic count (a 10-thread run answered at 9 tokens/s without it, 24 with it).
- The code page sent `reasoning_effort: high` whenever thinking was on; it now sends what the loaded model understands for the chosen level.
- KV block copies (several choices per request, swap preemption) work with KV pools whose layers have their own sizes.

- Vulkan: a new tiled matrix-matrix kernel for prompt processing with quantized weights (`mmq_<format>_i`, used from 32 rows up on GPUs with the int8 dot product), and the shaders now emit the dot-product instruction themselves when the shader compiler is too old to do it (the Windows release build was affected). Compiled and unit tested, not yet measured on a GPU; `FLLM_VK_MM=0` switches the kernel off, `FLLM_VK_MM_BM` / `FLLM_VK_MM_BN` tune the tile ([docs/changes/vulkan-prefill.md](docs/changes/vulkan-prefill.md)).
- NPU: a load option "What the NPU computes" (`--npu-mode all`): besides the long prompt blocks the NPU then also computes the single rows of the answer, the way later and stronger NPUs will be used. Measured on an Intel Core Ultra NPU with Qwen3.5-2B Q4_K_M: the answer runs at about 5 tokens/s this way (after a one-time compile of a few minutes that OpenVINO keeps in its cache), about as fast as the processor and well below the graphics chip.
- `--threads auto` (the new default): the CPU thread count follows the processor's topology (one thread per physical core; on hybrid processors all fast cores plus three quarters of the efficiency cores, never the low-power ones) and is confirmed by a measurement of about a second on the real weights at start-up, remembered per CPU, weight type and matrix shape (`FLLM_NO_AUTOTUNE=1` skips it). The old default of one thread per logical processor was less than half as fast for answers as 8 threads on a 14-thread hybrid laptop. Prompts keep all logical processors when all cores are alike; on Windows hybrid processors the process leaves power throttling and stays on the chosen cores (`FLLM_NO_PIN=1` disables that). `fllm-rs devices` and `/api/studio/hardware` report the topology and the thread count ([docs/cpu-kernels.md](docs/cpu-kernels.md#thread-count)).

### Fixed
