# Model coverage against vLLM and SGLang

Snapshot of 2026-10-13. Sources: vLLM `vllm/model_executor/models/registry.py` (main) and SGLang `python/sglang/srt/models/*.py` (`EntryClass`, main). The sources were only read to understand the architectures; no code was taken over. Architecture names are the class names in `config.json` (`architectures`); both engines look models up that way.

Test levels (L0-L3) are explained in [test-levels.md](test-levels.md).

## Result

In total 486 distinct architecture names across both registries (vLLM: 392, SGLang: 284, in both: 190). Of these, 13 are wrappers (`Transformers*`, `MindSpore*`: fallback to the Hugging Face implementation, not an architecture) and 96 are speculative draft/MTP heads.

| --- | --- | --- | --- | --- |
| Text generation (decoder) | 163 | 95 | 2 | 66 |
| Embedding / encoder / classification / reward | 70 | 18 | 0 | 52 |
| Multimodal (status = text part; vision/audio input only for SmolVLM) | 144 | 48 | 66 | 30 |
| Draft / MTP / EAGLE heads | 96 | 0 | 0 | 96 |
| Wrappers (not counted) | 13 | - | - | - |

Rows with several names are shared implementations (aliases). V/U/N count names, not rows.

Status legend:

* **V** supported and verified: fLLM's conversion of a tiny random checkpoint of this architecture agrees with `transformers` 5.19 (or, for remote-code models, with the model code): `scripts/verify_architectures.py` compares all positions, relative logit deviation < 2e-3, no arg-max difference. All 92 fixtures from `scripts/hf_golden.py` were re-run for this table and pass.
* **U** accepted by the converter/loader, but without a fixture or only partly checked (see the note).
* **N** not supported. An architecture only counts as supported if it appears in the converter (`rust/checkpoint/src/plan.rs`, `classic.rs`, `bert.rs`) AND in the loader (`rust/engine/src/model.rs` `SUPPORTED_ARCHITECTURES`, `config.rs`, `rust_decoder.rs`) AND a fixture exists. The converter keys on `model_type`, not on the class name; the `model_type` column shows the mapping.

Effort: **S** < 1 h, **M** 1-3 h, **L** > 3 h, each for the CPU path including converter and comparison against a reference (estimated, not measured). The figure for L groups with exotic layers can be considerably higher.

Column **Device path**: derived from `backend_unsupported()`, `layer_host_reason()` and `ffn_host_reason()` in `rust_decoder.rs` and from the config features (LayerNorm, parallel residual, activation, MLA, ShortConv, FFN-only layers, gate type). It is a reading of the code and was **not verified per architecture on a GPU**. A layer for which the selected backend has no kernel runs on the host reference code between the device layers (the residual stream is downloaded, the layer runs on the CPU with the host KV cache, and the stream goes back up); a model is only rejected on a device when every layer would run on the host, when it needs LayerNorm and the backend has none (the portable wgpu path), or when it uses grouped RMSNorm on backends without grouped norm support. `dbrx` and `lfm2moe` are the two architectures that require `--device cpu`. Values: `device` = every layer has a device kernel on the native backends; `hybrid` = attention layers on the device, recurrent layers (Mamba/DeltaNet) on the device where the backend has a recurrent kernel (CUDA: Mamba 1/2, DeltaNet, ShortConv, MLA; Vulkan and Metal: DeltaNet) and otherwise on the host between the device layers; `host layers (X)` = layers with feature X have no kernel on some or all backends and run on the host; `CPU only` = `--device` other than `cpu` is rejected with a message. Column **New GPU kernels**: what is missing for full GPU operation, or, for N rows, what would be needed in addition to the layers.

## Gap groups

The gaps (status N and U) are grouped into work groups that can be taken on independently. The order is the priority given by
adoption (downloads of the example models) divided by effort; home hardware (8-24 GB VRAM) first. Models of 300B and above have the same position in the tables, but come later
because of the effort and because they are hard to use. All groups are CPU / converter / loader work; the GPU part that is needed is listed in the last column and belongs to group M.
The same proof applies to every architecture: a mini checkpoint (random weights, 3 layers, hidden size 64) from `scripts/hf_golden.py`, conversion with `fllm-rs convert`,
comparison of all positions against `transformers` (or against the model's remote code) with a relative deviation < 2e-3; where llama.cpp GGUFs exist, the text is compared against llama.cpp as well. The correctness of large models is shown exclusively on mini checkpoints of the same architecture.

### Group details

**A - Aliases and small deviations (S).** The converter keys on `model_type`; many remote-code models are Llama/Qwen2/Gemma clones with a different
`model_type` and are therefore rejected only because of a missing entry in `family_for()` (`rust/checkpoint/src/plan.rs`). Procedure per model: read the config from the Hub, compare the tensor names
with the Llama mapping, add the alias (bias flags if needed), and build a fixture through `LlamaConfig` with a rewritten `model_type` or through the remote code.
`GraniteSWA` needs the sliding-window layer list **plus** per-head sinks (`self_attn.sinks`) and per-layer `layer_rope_theta` (NoPE) -> not a pure alias. Mistral Large 3 is DeepSeek-V3-like (MLA);
the `mistral_large_3` entry in the converter used to point to dense Llama and now points to `deepseek2`. Implementation: six alias entries in `family_for()` (`internlm3`, `iquestcoder`,
`xverse`, `mimo`, `solar`, `orion`), `mimo` with a filter against `model.mtp_layers.*` and a suppressed `nextn_predict_layers`, `solar` with the window pattern switched off, `xverse` with `default_theta` 10000.

**H - Embedding/encoder (M per model).** `ModernBERT`: alternating local (128) and global attention, two RoPE bases, GeGLU, LayerNorm without bias, the first pre-norm is omitted; transformers
has `modernbert` and `nomic_bert` (own converter + loader, fixture + nomic-embed-text-v1.5 verified). `GTE-new`: BERT with RoPE and GLU, without position embeddings (remote code, open). `EmbeddingGemma`: Gemma-3 backbone with a bidirectional mask, mean pooling, two dense layers. `SPLADE`: MLM head, `log(1+relu)`, max pooling over the sequence.
Server routes for token vectors (ColBERT) and sparse vectors are new. GPU: see `docs/inference-features.md` for what the encoder runs on the device.

**B - Older / small families (S-M per model).** (`InternLM2` and `Nemotron` are done.) `MiniCPM` (muP: `scale_emb`, `scale_depth/sqrt(layers)` on residuals, `dim_model_base` logit scaling),
`ChatGLM` (fused QKV, partial RoPE with pairs, fused SwiGLU; neighbour of `glm`), `Baichuan` (`W_pack`; 13B with ALiBi; NormHead), `Exaone 3` (own tensor names), `Solar` (block skip `bskcn`), `Orion` (LayerNorm instead of RMSNorm), `Qwen1`, `Persimmon`, `DeepSeek-MoE v1` (the GGUF arch `deepseek` is loaded, the HF converter is missing).
**Status:** `Persimmon` is implemented as its own GGUF arch (`persimmon`) and verified against transformers 5.19 (rel. 2.1e-4/2.2e-4, no arg-max difference). Persimmon is the only member of the group that exists natively in transformers; see the Persimmon row for its specifics (LayerNorm with bias, head-interleaved QKV, per-head Q/K LayerNorm with bias, ReLU2, partial RoPE 0.5, MHA). The other models have not been attempted: `exaone`, `TeleChat2`, `TeleFLM`, `Step1`, `Plamo3` are HF-gated (HTTP 401, config/tensors not readable); `ChatGLM`, `Baichuan`, `Qwen1`, `MiniCPM` and `DeepSeek-MoE v1` need remote code from 2023 that does not run under transformers 5.19 without custom shims.

**F - Gemma 3n / 4 (L).** Gemma 3n: per layer AltUp (4 parallel residual streams), LAuReL (low-rank residual), per-layer embeddings (PLE), KV sharing of the last layers with earlier ones, activation sparsity (Gaussian top-k) in the first MLPs.
Gemma 4: sliding 256x8 and global 512x2 (head width x KV heads), K=V on global layers, proportional partial RoPE, 26B A4B with a dense MLP next to the MoE block; E2B/E4B with PLE and KV sharing. Prerequisite is group G.

**C - Hybrids (M-L).** Order by benefit for home use: `Falcon-H1` (Mamba2 and attention in parallel in every layer, mu-P multipliers, sum of the branches; fLLM has Mamba2 and attention separately),
`Zamba2`, `Jamba` (Mamba-1 with inner layer norms + attention + MoE), `Kimi-Linear`/KDA (delta rule with a per-channel gate, `cpu_delta.rs` is the point to build on), `Ling 2.5/3.0` (lightning attention/KDA + MLA),
`GLM-5-Next`, `JetNemotron`, `Zaya`. KDA is a shared prerequisite of many 100B+ models.

**D - MoE gaps (M-L).** `Bailing v1/v2` first: Ling-mini-2.0 (16B/1.4B active) and Ling-flash-2.0 are relevant for home hardware, HF tiny checkpoints exist (`yujiepan/bailing-moe-v2-tiny-random`), but the converter currently maps `bailing_moe`
to MLA. After that `Cohere2Moe` (transformers class available), `Grok-1`, `Pangu`, `Param2MoE`, `XverseMoE`, `Step3`.

**G - Per-layer KV geometry (L, platform).** Today a model has one head geometry (`ModelConfig.kv_heads/head_dim/value_dim`). Needed: a list per layer, a cache block layout per layer, a K=V option (read V from K), and the loader key `head_count_kv`
as an array (already read for `nemotron_h`). After this group, MiMo-V2, Step-3.5, Laguna, Mellum, DeciLM and NemotronH-Puzzle are M each.

**E - DeepSeek successors and large models (L per model).** DSA: lightning indexer (small Q/K projection + ReLU score, top-k per token) in front of MLA; V4: mHC hyper-connections (several residual streams with learned mixing matrices),
compressed attention (CSA/HCA) and Engram embeddings. All 300B+ models can only be checked on mini checkpoints; the transformers classes (`deepseek_v32`, `deepseek_v4`, `glm_moe_dsa`, `longcat_flash`, `step3p5`, `mimo_v2_flash`, `hy_v4`, `qwen4_exp`, `inkling_text`, `kimi_linear`, `glm5_next`) are present in transformers 5.19 and give reference logits.
